# M-Film Digital Darkroom — AI Processing Extension

Техническая спецификация, версия 1.2 (09.11.2026)

**Назначение:** дополнить существующий серверный M-Film Digital Darkroom локальными нейросетевыми модулями RAW-проявки, сенсорного/цветового шумоподавления, автоматической коррекции, переноса цветового стиля и увеличения разрешения (AI Super-Resolution). Не переписывать действующий функционал без необходимости.

**Среда:** Linux, веб-интерфейс, CUDA; целевое GPU — NVIDIA Tesla V100 16 GB, возможность использования нескольких GPU.

**Принцип:** весь инференс выполняется локально, без облачных сервисов.

## 1. Границы задачи

Внедрить пять самостоятельных функциональных модулей:

1. **Modular Neural ISP** — нейросетевая первичная проявка цифровых RAW.
   Репозиторий: https://github.com/SamsungLabs/modular_neural_isp
2. **SA-LUT** — перенос визуального стиля (цвет и тон) с изображения-образца.
   Репозиторий: https://github.com/Ry3nG/SA-LUT
3. **Image-Adaptive 3D LUT** — автоматическая адаптивная цветотональная коррекция.
   Репозиторий: https://github.com/HuiZeng/Image-Adaptive-3DLUT
4. **Real-ESRGAN** — локальный нейросетевой апскейлинг фотографий.
   Репозиторий: https://github.com/xinntao/Real-ESRGAN
5. **AI Noise Reduction** — отдельный, управляемый нейросетевой денойзер для старых APS-C/Bayer сенсоров, особенно Nikon D5100: приоритет — цветовой шум без «акварельной» потери деталей.
   - RawNIND UtNet2 (Bayer RAW; основной кандидат): https://github.com/trougnouf/rawnind_jddc
   - RawForge / RawRefinery (ISO-aware, независимая регулировка chroma/luma; альтернативный кандидат): https://github.com/rymuelle/RawForge
   - NAFNet (RGB-обработка после проявки; резервный/сравнительный кандидат): https://github.com/megvii-research/NAFNet
   - Подготовленные ONNX-модели RawNIND/NAFNet в репозитории darktable-ai: https://github.com/darktable-org/darktable-ai

Модули дополняют существующие профили материала, камеры, плёнки, оптические эффекты, зерно, halation, предпросмотр и интеграцию с PhotoPrism.

**Важно:** обработка оцифрованных аналоговых негативов НЕ предусмотрена. Не реализовывать инверсию плёночных сканов, NegPy, обработку маски цветного негатива или другие функции для сканированных негативов. Под «негативом» здесь понимается **цифровой камерный RAW**.

## 2. Исходные данные и форматы

- Nikon `.NEF`, в первую очередь Nikon D5100;
- Canon `.CR2`, `.CR3`;
- `.DNG`, включая RAW из CHDK;
- остальные RAW, доступные действующему декодеру;
- `.TIFF`, `.PNG`, `.JPEG` — для совместимых постпроцессоров.

Оригиналы никогда не изменяются. Сохранять RAW-метаданные, ориентацию, EXIF и профиль цвета. Для нуждающихся в DNG модулей использовать временную конвертацию через существующий RAW-декодер либо DNGLab (https://github.com/dnglab/dnglab); предварительно проверить совместимость DNG с конкретной моделью и корректность CFA/black level/white level/цветовых матриц.

## 3. Модуль Modular Neural ISP

Интегрировать как **альтернативный** первичный RAW-движок, наряду с Classic RAW.

- Использовать официальную архитектуру и доступные предобученные веса.
- Реализовать адаптер `NeuralISPAdapter` с проверкой реальной поддержки используемого входного формата/камеры.
- В рамках поддерживаемых моделью возможностей обеспечить нейросетевое шумоподавление, баланс белого, цветовые преобразования, тональную обработку и детализацию.
- Не выдавать перечисленные операции за независимо управляемые, если архитектура модели не предоставляет соответствующих параметров.
- Поддержать повторный рендер с изменёнными параметрами и пакетный инференс.
- При недоступности/ошибке Neural ISP сохранять работоспособность Classic RAW.
- Избегать двойного применения баланса белого, демозаики, гаммы и цветовых матриц.

В UI: `RAW Engine: Classic | Neural ISP`; дополнительные контролы отображать лишь для реально поддерживаемых операций.

## 4. Модуль SA-LUT

Создать `StyleTransferAdapter` для обработки уже декодированных изображений.

- Принимать фотографию-образец из локальной загрузки, локальной библиотеки или PhotoPrism.
- Переносить визуальную цветотональную стилистику образца на целевое изображение в пределах возможностей метода.
- Контроль интенсивности 0–100%, возможность отключить модуль.
- Сравнение до/после; использование одного образца для пакетной обработки.
- Поддержать сохранение ссылки на референс и параметров в рецепте.
- Не обещать точного физического воспроизведения эмульсии или структуры зерна.
- Проверить возможности полноразмерного инференса и пиковую VRAM; при необходимости отдельный режим высокого качества или безопасная обработка блоками, только если архитектура допускает это без швов.

## 5. Модуль Image-Adaptive 3D LUT

Создать `AdaptiveLUTAdapter`:

- Автоматическая коррекция тона и цвета, локальный инференс.
- Управление интенсивностью 0–100%, включение/отключение.
- Возможность пакетной обработки с индивидуальным расчётом для каждого кадра.
- Если модель позволяет определять LUT на уменьшенной копии, применять полученный LUT ко всему кадру в высокоточной обработке.
- Не заменять AI-режим статической LUT без явного информирования.
- Проверить происхождение и совместимость предобученных весов.

## 6. Модуль Real-ESRGAN — нейросетевый апскейлинг

**Задача:** добавить локальное увеличение пространственного разрешения готовых к рендерингу цифровых фотографий без облачных API. Это отдельный постпроцессор **после декодирования/проявки RAW**, а не декодер RAW. Создать `UpscaleAdapter` с единым контрактом остальных адаптеров.

**Репозиторий:** https://github.com/xinntao/Real-ESRGAN

**Модели и режимы:**

- `RealESRGAN_x2plus` — штатный нейросетевой масштаб **×2**, основной режим для фотографий.
- `RealESRGAN_x4plus` — штатный нейросетевой масштаб **×4**, для значительного увеличения.
- `RealESRNet_x4plus` — опциональный альтернативный checkpoint для сравнительной оценки достоверности деталей и артефактов; включать только после тестирования на фотоматериале.
- Не использовать модели, обученные специально для anime, в качестве режима по умолчанию для фотографий.
- Пользовательский масштаб `1.5× / 2× / 3× / 4×`: для промежуточных величин использовать штатный вывод поддерживаемой модели с последующим качественным ресайзом (например, Lanczos); не утверждать, будто модель нейросетевым способом непосредственно генерирует любой дробный коэффициент. При необходимости добавить точное задание длинной стороны или размера печати.

**Веб-параметры:** включено/выключено; модель/профиль; масштаб; опциональное ограничение выходных мегапикселей; режим «сохранение естественной фактуры» (только через реально проверенную модель/смесь с обычным ресайзом, а не фиктивный параметр модели). Выводить оценку итогового разрешения и предупреждение о большом размере результата **до запуска**. Не объединять настройку силы denoise с базовыми `x2plus`/`x4plus`: отдельный параметр `denoise_strength` документирован только для `realesr-general-x4v3` и должен появляться лишь при выборе этой модели, если она будет дополнительно интегрирована.

**Фотографическое качество:**

- Апскейлер может **синтезировать правдоподобные детали**, отсутствующие в исходнике; не считать созданную детализацию фактически достоверной. Для архивных/документальных изображений предусмотреть отключение AI и классический Lanczos.
- Предусмотреть сравнение 100%-кропов до/после и отображение артефактов на лицах, текстурах, тонких линиях, волосах, краях и высококонтрастных участках.
- Исключить двойную резкость и двойное шумоподавление при совместном использовании с Neural ISP; по возможности дать независимое отключение апскейлинга для конкретного рецепта.
- Приоритетный порядок: **профиль камеры → первичная проявка → цветотональная коррекция / SA-LUT → моделирование тональности/цвета плёнки → AI upscale → финальное плёночное зерно и halation → экспорт**. При интеграции с существующим движком учесть, что оптические эффекты могут быть частью единой стадии: не перестраивать без проверки физики эффекта и результата. AI-апскейлер не должен увеличивать уже нарисованное зерно как структуры исходного кадра.

**Инференс и память:**

- Использовать PyTorch/CUDA-реализацию с официальными весами; для Tesla V100 проверить FP16 и FP32.
- Обязателен **tiled inference** с `tile`, `tile_pad`, пограничным перекрытием, контролем отсутствия швов и автоматическим уменьшением размера тайла при CUDA OOM. Начальный размер тайла выбирать экспериментально, без обещания фиксированной потребности VRAM.
- Обрабатывать выходные изображения потоково / блоками там, где возможно; избегать одновременного хранения нескольких полных копий 4× кадра в VRAM и RAM. Для 16 Мп входа ×2 даёт около 64 Мп, ×4 — около 256 Мп; предусмотреть ограничения по RAM, дисковому месту и TIFF/BigTIFF для файлов более 4 ГБ.
- Конверсию рабочего пространства в допустимый для сети диапазон выполнять внутри адаптера и возвращать результат в рабочее цветовое пространство. Указанная в официальном коде поддержка 16-bit **на входе** не равнозначна сохранению всей 16-битной RAW-точности нейросетью: проверять градации, цветовой охват и бэндинг на тестовых кадрах.
- Инференс в preview выполнять для выбранного кропа высокого разрешения; полноразмерный апскейлинг запускать только при финальном рендере. Кешировать промежуточные стадии и показывать прогресс по тайлам.

**Условия приёмки модуля:** реальный CUDA-инференс ×2 и ×4, корректные размеры выходных файлов, отсутствие тайловых швов, корректная цветопередача и EXIF, сохранение исходного RAW, устойчивость на V100 16 ГБ и рабочий fallback на обычный ресайз при недоступности AI.

## 6A. Модуль AI Noise Reduction — нейросетевое удаление шума APS-C RAW

**Назначение:** повысить качество кадров со старых CMOS/Bayer-матриц, в первую очередь **Nikon D5100, 16,2 Мп**, снятых на высоких ISO либо вытянутых из недоэкспонированных теней. Главный дефект — **chroma noise** (цветные красно-зелёно-синие точки и пятна); второстепенно — luminance noise (монохромная зернистость). Уменьшать шум, **не превращая волосы, кожу, листву, ткани и мелкие детали в «масляную живопись»**. Новые, не существовавшие в RAW детали нельзя считать достоверно восстановленными.

### 6A.1. Модели и выбор движка

**A. RawNIND UtNet2 (приоритетный RAW-кандидат).**

- Исходники и веса: https://github.com/trougnouf/rawnind_jddc ; пакетирование/конвертация в ONNX: https://github.com/darktable-org/darktable-ai/tree/master/models/rawdenoise-nind
- Работа с Bayer RAW в **packed [R,G1,G2,B]** после корректного вычитания black level и нормализации к white level; модель **совместно выполняет шумоподавление и демозаику**: packed Bayer -> 3-канальный camRGB с исходной пространственной размерностью.
- Для имеющегося ONNX-пакета входные тайлы **[1,4,512,512]**, выходные **[1,3,1024,1024]**; точность FP32, opset 20. Адаптер обязан сделать реальную трансформацию CFA pattern/ориентации и собрать полное изображение без швов.
- Выходной camRGB привести к линейному рабочему RGB через матрицы цвета камеры; учесть документированную **gain matching** процедуру модели. Получившийся RGB **не отправлять на повторную демозаику**.
- Данный вариант **заменяет штатную демозаику на своей ветке**. Не подавать его результат в RAW-only Neural ISP как будто это Bayer RAW; Neural ISP и RawNIND должны быть совместимы лишь там, где их реальные входные контракты допускают каскадирование.
- Предобученные веса обучены на RawNIND, а не на конкретной Nikon D5100; эффективность и цветовую точность проверить на реальных `.NEF` пользователя, до включения режима по умолчанию.

**B. RawForge / RawRefinery (экспериментальный альтернативный RAW-кандидат, особенно для раздельного chroma/luma).**

- Репозитории: https://github.com/rymuelle/RawForge и https://github.com/rymuelle/RawRefinery ; поддерживаются модели семейства `TreeNetDenoise*`, в том числе `TreeNetDenoiseHeavy`.
- В CLI RawForge доступны `--lumi`, `--chroma`, `--conditioning` (ISO conditioning), `--tile_size`, `--device`, `--cfa`; ONNX-вариант — `rawforgeonnx` (CUDA EP — после проверки установленного окружения). Не делать вид, что параметр есть в модели, если на самом деле это blend в адаптере.
- Рассмотреть экспорт промежуточного **CFA DNG** с сохранением RAW-метаданных (чтобы затем работали Classic RAW/при возможности Neural ISP) либо прямой выход в линейный RGB, исходя из проверенного реального поведения CLI.
- Этот проект находится в состоянии **alpha**; приоритет — корректность цвета, metadata/CFA и DNG совместимость. Проверить известные проблемы с матрицами цвета, TIFF/DNG-тегами и файлами Nikon.
- Пользовательские регуляторы chroma/luma выводить непосредственно из реально поддерживаемых параметров RawForge. ISO conditioning автоматически задавать по EXIF с возможностью коррекции.

**C. NAFNet SIDD (резервный RGB-денойзер).**

- Исходники: https://github.com/megvii-research/NAFNet ; ONNX модель: https://github.com/darktable-org/darktable-ai/tree/master/models/denoise-nafnet
- Работает с 3-канальным **RGB после демозаики**, а **не с цифровым Bayer RAW**. Вариант darktable-ai: вход `[1,3,768,768]`, FP32, диапазон [0,1], тайлы 768 px.
- Модель обучалась на реальном шуме смартфонов (SIDD), поэтому её переносимость на старую APS-C Nikon D5100 **не гарантирована**. Использовать как benchmark/альтернативу, а не как подтверждённо лучший движок.

Проверять сначала A и B на одних и тех же реальных кадрах; C — для готового RGB или случаев, когда RAW-модели недоступны. Не включать все три подряд: это создаёт двойной denoise и повышает риск потери текстур.

### 6A.2. Параметры веб-интерфейса

Добавить блок **AI Denoise**:

- `enabled`: да/нет; `engine`: `RawNIND` / `RawForge` / `NAFNet RGB` / `Off` (отображать лишь доступные движки).
- `chroma_strength`: подавление **цветового** шума, шкала 0–100%, приоритетный орган управления (реализация через параметр модели либо корректное раздельное смешивание цветовых компонент в подходящем RGB-пространстве; для Bayer ветки проверять отсутствие цветовых артефактов).
- `luma_strength`: подавление **яркостного** шума, 0–100%, независимое от chroma; не эмулировать неподдерживаемую силу нейросети вымышленной командой.
- `detail_preservation`: возврат фактической высокочастотной информации при смешивании оригинала с результатом, не цветных шумовых пятен; предусмотреть высокочастотную DWT/частотную маску там, где она корректно работает.
- `iso_mode`: Auto из EXIF либо Manual, если выбранный движок поддерживает ISO conditioning.
- Предустановки `Natural` (по умолчанию), `High ISO`, `Strong chroma`, `Minimal smoothing`; это **наборы реальных параметров**, не отдельные вымышленные модели.
- 100%-кроп выбранной зоны и сравнение `Original / Denoised / Difference` со split-view. Для качества обязательно смотреть лицо, волосы, мелкий текст, листву, ровные тени и гладкие цветовые градиенты.
- Режим «Не создавать искусственную фактуру»: отключить непроверенную GAN/генеративную реконструкцию; при неудачной обработке выбрать Classic RAW без AI.

### 6A.3. Порядок стадий и совместимость

- **RawNIND:** исходный RAW -> извлечение Bayer/метаданных -> RawNIND denoise+demosaic -> линейный рабочий RGB -> последующие стадии M-Film.
- **RawForge с CFA DNG:** исходный RAW -> RawForge -> временный денойзенный CFA DNG -> Classic RAW decoder/demosaic -> линейный RGB -> M-Film. Связь с Neural ISP включать только после проверки форматов.
- **NAFNet:** исходный RAW -> Classic RAW/поддерживаемый Neural ISP -> RGB denoise -> M-Film.
- **Нельзя** механически выполнять `RawNIND -> Classic demosaic` или `RawNIND -> Neural ISP`, ожидающий исходную мозаичную структуру.
- На одном кадре по умолчанию должен быть **один основной денойзер**: либо входящий в Neural ISP, либо отдельный AI Noise Reduction. При необходимости пользователь может выбрать исключение, но интерфейс обязан предупреждать о двойной обработке и предлагать отключение denoise внутри ISP (только если его архитектура это поддерживает).
- AI-шумоподавление выполнять **до** переноса стиля, плёночных кривых, апскейлинга и финальных эффектов плёнки. Плёночное зерно, halation, bloom создавать **после** denoise, иначе они будут приняты за шум и удалены.
- Исходный `.NEF` никогда не изменять. При наличии промежуточного `.DNG` проверять CFA, black/white levels, ColorMatrix/AsShotNeutral, ориентацию, crop и EXIF. Для RawNIND сохранять рабочее линейное изображение в корректном цветовом пространстве, не пытаться выдавать его за необработанный Bayer DNG.

### 6A.4. Инференс, GPU и QA

- Целевое GPU — **Tesla V100 16 GB**; приоритет CUDA/ONNX Runtime с соответствующим CUDA Execution Provider, PyTorch как резерв. Проверить поддержку Volta/FP32/FP16 и конкретных операций ONNX opset 20 на установленном runtime. FP16 использовать только после проверки численной устойчивости/отсутствия артефактов.
- Должны работать **плиточная обработка с перекрытием**, реконструкция швов, автоуменьшение тайла при OOM (если размер модели динамический; у фиксированной ONNX-модели использовать более малое количество одновременных тайлов, а не менять размер входа наугад), model offload, ограничение числа worker-процессов.
- Сделать тестовый набор Nikon D5100 (низкие ISO, ISO 800/1600/3200/6400 где имеются, недоэкспонированные тени) и дополнительно Canon RAW. Оценивать на 100% и при уменьшении до экранного разрешения: ложные цветовые пятна, кожа/волосы, листья, тонкие края, реальная детализация, повторяемость цветов, швы, halos.
- Сравнить RAW с `Classic RAW без denoise`, `darktable profiled denoise`, `RawNIND`, `RawForge` и `NAFNet`, плюс вариант с мягким chroma-only denoise. **Не заявлять превосходство без прямого сравнения** на одних и тех же кадрах.
- Пиковые VRAM/RAM и время инференса зафиксировать для 100%-кропа, полного 16,2 Мп кадра и batch. Не использовать вымышленные оценки памяти как гарантию. При невозможности безопасного запуска полного кадра реализовать корректную деградацию качества/скорости или понятную ошибку без падения backend.
- Критерий качества: нейтрализация цветных пятен в тенях **без необратимого размазывания кожи, волос, ткани и мелких деталей**. Установить тестовые визуальные эталоны, утверждать дефолтный движок только по ним.

## 7. Конвейер обработки

```text
Digital RAW (.NEF/.CR2/.CR3/.DNG)
    -> AI Denoise RAW (optional, mutually exclusive branches):
         A) RawNIND = denoise + demosaic -> linear RGB (no second demosaic)
         B) RawForge = denoised CFA DNG -> Classic RAW demosaic (if verified)
         C) Off -> Classic RAW OR Modular Neural ISP
    -> AI Denoise RGB (NAFNet optional, only after demosaic; avoid double denoise)
    -> Image-Adaptive 3D LUT (optional)
    -> SA-LUT style transfer (optional)
    -> Existing M-Film camera / material / film color-tone simulation
    -> Real-ESRGAN AI upscale (optional; full render or preview crop)
    -> Existing grain / halation / final optical effects
    -> Preview OR full-resolution render
    -> Export / PhotoPrism
```

Это последовательность по умолчанию; согласовать её с существующим кодом и учесть цветовые пространства каждой стадии. Явно описать контракты стадий (RGB linear/sRGB, gamut, gamma, bit depth, scaling, alpha). Не допускать скрытого перехода в 8-bit на основных стадиях. Для моделей, требующих ограниченного диапазона данных, выполнять преобразование в/из этого диапазона строго внутри адаптера. Сохранять высокую точность исходных данных, насколько позволяют модели.

Плёночное зерно и halation преимущественно применять **после** AI-коррекции и апскейлинга, чтобы нейросеть не подавляла и не увеличивала сформированную плёночную фактуру. При работе с существующим симулятором плёнки не ломать порядок его штатных стадий.

## 8. Backend и модельные адаптеры

Абстракция (реализовать в парадигме существующего стека, не переписывая приложение):

```text
InferenceBackend
    NeuralISPAdapter
    DenoiseAdapter  (RawNIND | RawForge | NAFNet)
    AdaptiveLUTAdapter
```

- отмена заданий, таймауты, обработка ошибок;
- логирование версии кода/модели/весов, статистики памяти и времени;
- загрузка весов из проверенного локального хранилища, контрольные суммы;
- изоляция зависимостей отдельными worker-процессами/окружениями при несовместимостях.

Никакого автоматического скачивания исполняемого кода из непроверенного источника в рабочем окружении. Не устанавливать конфликтующие версии PyTorch в основной Python-процесс приложения.

## 9. CUDA / Tesla V100 / VRAM

- Работать с Tesla V100 16 GB (Volta, compute capability 7.0), проверить совместимость конкретных CUDA/PyTorch сборок и кастомных расширений.
- Не требовать BF16; проверять FP32 и FP16 и численную корректность на V100.
- Поддержать несколько GPU и распределение заданий без обязательного NVLink.
- Модели загружать по требованию; последовательная работа на одном GPU — поведение по умолчанию.
- Начиная с экспериментального лимита примерно **14 GB** на AI-задачи V100, оставлять резерв под контекст и промежуточные буферы. Лимит конфигурируемый, не гарантирует отсутствие OOM.
- Scheduler контролирует свободную VRAM, очередь, concurrency, освобождение ресурсов, отказоустойчивость и повторное выполнение с меньшими тайлами, если алгоритм это допускает.
- Не рассчитывать, что все пять функциональных модулей и их альтернативные модели поместятся одновременно: измерить реальные пики VRAM на целевых разрешениях.
- Для full resolution применить tiled inference с overlap только к операциям, где это математически корректно; глобальные цветовые преобразования не вычислять независимо по тайлам. Для Real-ESRGAN обязателен контроль `tile`/`tile_pad`, мониторинг памяти и автоматическая деградация размера тайла при OOM. Планировать отдельно VRAM инференса и RAM/диск для выходного кадра ×4.

Провести бенчмарки на 1080p/2048px preview, Nikon D5100 16 MP (включая RAW-денойзинг, chroma/luma, Real-ESRGAN ×2/×4 и тайлы) и дополнительном RAW высокого разрешения: холодный/тёплый старт, пик VRAM, latency, качество, отсутствие OOM.

## 10. Веб-интерфейс

Сохранить действующий сценарий M-Film: **материал -> камера -> плёнка -> параметры -> предпросмотр -> проявка**.

Добавить секцию **AI-проявка**:

- `RAW Engine`: Classic / Neural ISP.
- `Neural ISP`: включение, поддерживаемые реальные настройки, статус модели.
- `AI Denoise`: `Off / RawNIND / RawForge / NAFNet`, независимые chroma/luma, сохранение деталей, ISO Auto/Manual (если доступно), пресеты и 100%-кроп; избегать двойного denoise в ISP.
- `AI Auto Correction`: on/off и интенсивность 0–100%.
- `AI Style Transfer`: on/off, референс (загрузка / PhotoPrism / библиотека), интенсивность 0–100%.
- `AI Upscale`: on/off, модель (`x2plus`, `x4plus`; дополнительные только после проверки), масштаб, целевой размер, лимит выходных мегапикселей и прогноз размера файла.
- Для апскейлинга: 100%-кроп в режиме до/после; не запускать апскейлинг всего кадра на каждом движении регулятора.
- Сравнение Before/After, split-view, масштабирование 100%.
- Просмотр выполняемого процесса, ошибки, отмена, повтор.
- Сохранение/загрузка именованного рецепта.

Предпросмотр асинхронный: при изменении параметров отменять устаревшие задания, кешировать неизменённые стадии и возвращать актуальный результат. Значение 0% для любого эффекта обязано давать идентичный результат варианту с отключённым эффектом (с оговоркой допустимого численного округления).

## 11. Preview и Final Render

**Preview:** разумная копия 1600–2048 px по длинной стороне; кеш стадий, быстрый отклик, отменяемые задания, корректная ориентация.

**Final:** исходное разрешение либо явно выбранное увеличенное разрешение после AI upscale, неизменные пропорции, высокоточная обработка где доступна, сохранение EXIF/ориентации/цветового профиля, форматы JPEG и TIFF 16-bit.
